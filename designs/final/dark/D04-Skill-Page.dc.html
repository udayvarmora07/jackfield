Write a test that fails for the right reason before you change any code. Then write the least code that makes it pass, and tidy up while the tests stay green.

When to use it

  • Adding a feature with clear inputs and outputs.
  • Fixing a bug: first write a test that shows the bug.
  • Changing code that has no tests yet.

Steps

  1. Write one small test for the next behavior. Run it and watch it fail.
  2. Write the simplest code that makes it pass.
  3. Run the whole suite. Tidy up only while everything is green.
  4. Repeat with the next behavior.
