Clickable prototype

The 14 approved screens, exactly as they were approved on the canvas, linked along the main flows. It works offline: open any file straight from this folder. The moon button on desktop screens switches light and dark.

What is real here: links between pages, the theme switch, and a few in-place states. Buttons that act in place (Turn off, Save, Fix) show their Undo state, or do nothing. They don't go anywhere, because in the product they don't either. The search palette (screen 13) has no link into it: open it from the list below.

Flows to try

  1. Turn a skill off for one agent (the success task). Skills table: the side panel shows code-review in Codex. Choose “Turn off in Codex”, then try “Why isn't it running?”.
  2. Read, then edit a skill. Skills table → side panel “Open skill” → Skill page → Edit → Editor (look at the Save-to card).
  3. Create a skill. Skills table → New skill → New skill with its live preview.
  4. Fix what needs attention. Skills table banner → “Fix one by one” → Needs attention → Open skill.
  5. Advanced and settings. Advanced → Shorten → tool page → AI settings → Settings.
  6. Recover. Top bar → Trash & backups.

How it runs

Each .dc.html file is a canvas template. support.js is the canvas runtime (it bundles React, MIT licence), copied from the canvas artifact so the screens render without an account or internet. Fonts come from fonts/ (IBM Plex, SIL OFL 1.1) in place of Google Fonts. Apart from that one link, the screens are unchanged from canvas version 36. This is a design prototype, not product code: the build uses the vendored Vue app in skillsmgr/webui/.
