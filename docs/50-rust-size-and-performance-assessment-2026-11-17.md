# Rust, Size and Performance Assessment — 2026-11-17

**Version 0.1.0**

**AI manifest**: Measured assessment for the maintainer's smaller/faster-app
request, including conditional permission to change languages or stack. The
shipping reference is `d97072e`: Python 3.11–3.14 CLI/HTTP backend, vendored
Vue 3.5.13, filesystem authority and rebuildable SQLite. This report separates
measured product behavior, external project claims, proposed targets and
unmeasured migration possibilities. Final delivery evidence is in
@docs/06-progress-log.md.

## Recommendation

**[SPEC]** Keep Python + Vue as the shipping implementation for this pass.
Remove measured duplication first. Evaluate Rust behind a compatible read-only
boundary only when an equivalent end-to-end prototype beats the optimized
reference enough to justify native packaging and maintenance. Do not infer a
whole-app improvement from another project's benchmark, a parser microbenchmark,
a small executable, or the language's popularity.

This is a decision about the present evidence, not a permanent rejection of
Rust. The maintainer has authorized a justified migration; no language,
framework, filesystem layout, schema or new runtime dependency changes in this
pass. There is no one stack that simultaneously minimizes development effort,
fresh installation footprint, latency, memory, compatibility and release cost.

## What this app actually ships

**[SPEC]** The baseline wheel built through the hash-locked toolchain contains
1,069,942 bytes (about 1.02 MiB). It does not bundle Python or a browser. Its
ZIP member groups, excluding ZIP container overhead, are:

| Group | Uncompressed bytes | ZIP-compressed bytes |
|---|---:|---:|
| Python source, 70 files | 1,304,166 | 373,291 |
| Fonts, 14 files | 401,784 | 401,255 |
| Vendored Vue | 157,924 | 57,677 |
| Classic/shared HTML, JS and CSS | 406,527 | 89,811 |
| Other v2 HTML, JS and CSS | 427,879 | 110,715 |
| Completion and management skill | 22,550 | 6,649 |
| Packaging metadata | 36,802 | 15,748 |

A rewrite would not automatically remove the fonts, Vue, the interfaces or
skill data. Four Plex Sans weight files were byte-identical copies of the
400-weight resources: 153,352 uncompressed bytes. Sharing those resources
retains all twelve font-face weight/style/range declarations and their exact
font bytes. Prototype references must follow the same resource consolidation.
The clean rebuilt wheel is 916,682 bytes (about 0.87 MiB): 153,260 bytes, or
14.32%, smaller including the scan optimization. All final package/install
payloads are checked against source. The isolated wheel target contains
4,258,350 file bytes including generated bytecode and distribution metadata;
it excludes Python and the browser, and is not filesystem allocated size. An incremental build retained deleted
files in ignored build output; the package gate rejected it, and a clean source
snapshot supplied the final artifacts. No gate was relaxed.

**[SPEC]** Compare three separate size measurements when evaluating Rust:
compressed download; installed application-owned bytes; and total incremental
fresh-machine footprint. If Python and a browser already exist, their full
installation sizes are not new application bytes. If they must be installed,
count them. Apply the same rule to native shared libraries, SQLite, TLS roots,
WebViews, runtime downloads, caches and updater packages. Do not compare an
isolated Python wheel to an entire desktop installer, or a Rust executable to
a running browser process tree. Repository `.git`, docs, prototypes and build
environments are development storage, not shipped application size.

## Current performance evidence

**[NOTE]** Disposable synthetic fixtures use isolated HOME/data/XDG/CODEX paths
and 126-byte skill documents. No personal skills, telemetry or live provider
calls are used. New Python processes run against warm filesystem page caches;
OS disk caches were not flushed. These are local samples, not portable SLOs,
real-library measurements or user-experience results.

The initial three-sample medians were 11.1 ms for an empty Python process and
107.2 ms for importing the CLI. At 1,000 agent skills, serialized CLI list and
hygiene medians were about 400 and 916 ms. Single 10,000-skill observations were
about 2.68 and 8.69 seconds, with peak backend RSS around 151 and 147 MiB.
A single large sample cannot establish a distribution or p95. This does not
measure browser startup, total GUI memory or frontend interaction latency.

The instrumented 1,000-skill hygiene profile showed two physical scope scans
and 2,000 `load_skill` calls. It recorded 8,013 realpath and 62,072 lstat calls.
The CLI list profile spent material time in scanning and JSON output as well
as frontmatter parsing. Instrumentation changes timing; cumulative call times
nest and must not be added as independent costs. The syscall tracer includes
process startup. The evidence identifies repeated work; it does not establish
how fast an equivalent Rust implementation would be.

**[NOTE]** A separate controlled experiment compares baseline and candidate
source snapshots with bytecode compiled consistently. Three paired invocations
per size alternate order and include CLI JSON serialization. Shared-host
browser activity existed, so ranges and sample counts matter. Final candidate
corrected-code results are:

| Agent skills | Before median (range), ms | After median (range), ms | Median reduction |
|---:|---:|---:|---:|
| 1,000 | 829.5 (812.3–873.2) | 674.6 (664.5–674.8) | 18.7% |
| 10,000 | 8,127.2 (7,954.7–8,160.3) | 6,045.1 (5,824.5–6,306.4) | 25.6% |

All retained runs exited zero. Per-sample wall/CPU/RSS and candidate source
hashes are in @benchmarks/rust-assessment-2026-11-17.json. This experiment is
independent of the initial profiling run; do not combine their timings into
one trend. Three samples do not support p95 or a portable guarantee. The
improvement applies to combined single-agent Doctor/hygiene requests, not
all-scope scans, startup, browser rendering or Rust.

The candidate shares one diagnostic observation between single-agent Doctor
and hygiene within one request. Doctor retains husks; hygiene excludes them
and recomputes affected duplicate annotations. Collector failures remain
visible, repeated requests observe new filesystem state, and standalone/global/
all-scope paths retain their contracts. A layout requiring different discovery
semantics must fall back or reject the optimization, never hide malformed
files to make a timing smaller. This is not a persistent inventory cache.

## What Rust would and would not change

| Option | Potential advantage | Cost and decision for this app |
|---|---|---|
| Optimize existing Python + Vue | Removes duplicate work and assets with the smallest parity burden | First choice for measured duplication. Interpreter and browser remain. |
| Optional Rust module, e.g. PyO3 | Faster measured CPU-heavy operations while retaining the product | Python still required; conversions/imports, native wheels, ABI and fallback complicate distribution. Prototype only after profiling. |
| Rust CLI/backend + existing Vue | Python-independent binary and potential startup/CPU/RSS benefits | Reimplement filesystem, parser, CLI/REST, recovery and release behavior; browser costs remain. A plausible later comparison, not yet a measured win. |
| Tauri + existing Vue | Desktop shell with system WebView and reusable web interface | Still a multiprocess web UI, plus IPC/update/OS runtime concerns. Appropriate only if a desktop shell is itself wanted. |
| Rust native UI, GPUI/Iced/Slint | Can avoid a browser/WebView engine for the interface | Requires a new UI and toolkit-specific accessibility, graphics, platform, licensing and feature work. Largest UI parity risk. |
| Full Rust rewrite | Removes Python and can consolidate a future native architecture | Highest delivery, correctness, recovery and maintenance burden. No equivalent prototype currently proves it worthwhile. |
| Go backend + existing Vue | Another native distribution option with a different development/runtime tradeoff | Same product parity obligations; GC behavior and SQLite/cgo packaging depend on implementation. No current benchmark selects it. |

**[SPEC]** Rust is valuable for native execution, control of allocation and
memory-safe concurrency. Safe Rust does not eliminate logic bugs, symlink races,
path traversal, hostile archives, authorization mistakes, local HTTP exposure
or unsafe/FFI dependency defects. Preserve this repository's safety contracts
regardless of language. See the [Rust unsafe boundary](https://doc.rust-lang.org/book/ch20-01-unsafe-rust.html).

Native binaries also have size/performance tradeoffs. Cargo supports stripping,
LTO and size-oriented optimization, but its documentation explicitly warns
that higher levels need not be faster and `s`/`z` need not be smallest. Measure
actual builds rather than adopting flags as promises. [Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html).

PyO3's `abi3` can reduce Python-version wheel combinations, but not the OS/CPU/
libc build matrix; it limits APIs and does not remove Python. Free-threaded
Python has additional ABI considerations. Pin released versions and audit FFI,
source builds, signing and artifact provenance. [PyO3 distribution guide](https://pyo3.rs/main/building-and-distribution),
[maturin distribution](https://www.maturin.rs/distribution.html).

Tauri uses system WebViews, so a small executable does not imply zero browser
runtime, a single process or identical rendering on every platform. Windows
WebView2 delivery choices can change installation size materially. Electron
bundles Chromium/Node and has different runtime accounting. Skills Manager
currently uses an existing browser and does not ship Electron.
[Tauri process model](https://v2.tauri.app/concept/process-model/),
[Tauri Windows installers](https://v2.tauri.app/distribute/windows-installer/),
[Electron architecture](https://www.electronjs.org/docs/latest/tutorial/process-model).

Native toolkits can remove the WebView layer but introduce different concerns.
[GPUI](https://www.gpui.rs/), [Iced](https://github.com/iced-rs/iced) and
[Slint](https://docs.slint.dev/) must be evaluated for this application's exact
widgets, keyboard/screen-reader behavior, target graphics stack, supported OS
versions and applicable license. Rendering speed alone is not a complete
application-quality verdict. No native GUI parity or speed result is claimed.

## Why other projects are choosing Rust

**[NOTE]** [uv](https://github.com/astral-sh/uv) is a successful Rust tool serving
Python users. Its dependency-resolution and installation benchmark is evidence
for that workload, not a multiplier for this application's scans or UI.

The Discord CTO's [2026-11-04 primary post](https://x.com/svishnevskiy/status/2118081920194203799)
was retrieved through agent-reach's OpenCLI-backed Twitter channel. It confirms
work toward replacing Electron with a Rust/GPUI client and says user testing
is upcoming. It does not demonstrate general availability or independently
reproduced RAM/speed numbers. Discord's [2020 Go-to-Rust article](https://discord.com/blog/why-discord-is-switching-from-go-to-rust)
concerns its server-side Read States service; it is a different migration.
Replacing a bundled browser engine and rewriting this app's Python backend are
not equivalent changes.

## Frontend, setup and next decisions

**[SPEC]** Changing the backend language does not fix a large DOM, repeated
browser computations, oversized JSON, eager tool-page loading or unnecessary
font requests. Profile those independently. Vue's guidance covers lazy chunks,
virtualization and reducing reactivity overhead; precompiled templates avoid
the runtime compiler but add build tooling. Their documented approximate
14 kB min+gzip compiler saving alone does not justify rebuilding this whole
application. [Vue performance guide](https://vuejs.org/guide/best-practices/performance.html).

Keep filesystem reads authoritative. Request coalescing and one-request reuse
are different from serving a stale inventory or trusting SQLite as source.
Changing to an async HTTP framework cannot, by itself, remove repeated scans,
serialization or browser work. An always-running daemon may reduce CLI startup
but adds background state, memory and an access boundary; it is not free speed.

**[NOTE] Proposed migration gates, not measured targets:** benchmark equivalent
CLI and UI tasks on representative zero/normal/large libraries; compare p50/p95
only with enough successful samples; account for full process-tree memory and
fresh/incremental install size; require exact error/JSON/exit-code and recovery
parity before any default replacement. Establish a material improvement beyond
noise and acceptable ongoing release costs. Test Linux, macOS and Windows,
including non-UTF-8 files, links, malformed documents, interrupts and concurrent
writers. Keep the Python reference and a proven rollback until a replacement
passes every required contract. Rust compiler availability on this laptop is
not evidence of product portability or a migration's benefits.

Use the least invasive implementation that meets the agreed outcomes. A narrow,
read-only Rust prototype is the next language experiment if a remaining CPU or
distribution bottleneck warrants it; a full rewrite is not the next automatic
step. The conditional migration authorization remains available when evidence
supports using it.
